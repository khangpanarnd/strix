What you get

A pentest team you run from the terminal.

Not a scanner that dumps a list of maybes. Strix proves what’s real, keeps the work on your machine, and fits the way you already ship.

Every finding is proven

Agents build a working exploit and save the request and response, so you triage facts instead of guesses.

Runs in a local sandbox

The agents attack from a Docker container on your machine. No vendor cloud runs the scan.

A viewer that explains itself

Run strix view for validated vulnerabilities, a live agent graph, run history and reports.

Drops into your pipeline

-n runs headless and exits 2 when it finds vulnerabilities. --fail-on sets the severity that fails the build.

Reports you can hand off

Each run writes Markdown, HTML, per-finding notes, vulnerabilities.json and findings.sarif (SARIF 2.1.0) into strix_runs/, so results drop straight into the tools your team already uses.

What you can scan

Code on disk, a repo, or a live app.

Same command shape, different target. Add --target-list to queue several at once.

A local folder

Point at source already on disk.

strix --target ./app-directory

A Git repository

Clone and scan straight from a URL.

strix --target https://github.com/org/repo

A running web app

Attack a staging URL end to end.

strix --target https://your-app.com

An authenticated flow

Hand it a dedicated test account.

strix --target https://your-app.com --instruction "test as user:pass"
Quick start

From zero to a first scan.

The first run pulls the sandbox image, so allow a few minutes. Model settings are saved to ~/.strix/cli-config.json, so you only set them once.

  • Docker installed and runningThe agents work inside a container.
  • Python 3.12+ and uvTo run Strix from this repository.
  • An LLM API keyFrom a provider your team has approved.
  • Permission to test, and a clean git stateA local folder is mounted writable, so commit or stash first.
terminal · three commands

1 · Run a quick scan on the current directory

uv run strix -n --target ./ --scan-mode quick

2 · Scan only what changed against main

strix -n --target ./ --scan-mode quick --scope-mode diff --diff-base origin/main

3 · Open the results

strix view

Scan mode defaults to deep. Cap spend with --max-budget-usd, continue a run with --resume. -n skips the interactive screen and exits 2 on findings.

Data and safety

Know where your data goes.

Strix runs on your machine, but it isn’t air-gapped. Here is what stays, what leaves, and what the agent can touch.

stays localOn your machine

  • The sandbox, where the agents run and attack
  • Every finding, log and report in strix_runs/
  • The viewer, which listens on 127.0.0.1 by default

leavesGoes off the machine

  • Agent prompts, including the code and responses they analyse, go to your model provider. Use an internal endpoint or a local model for sensitive code.
  • Anonymous usage counts go to PostHog and Scarf by default: versions, model name, scan mode, finding counts, token and cost totals, error class names. Set STRIX_TELEMETRY=0 to turn it off.

Test only what you own. Strix runs real exploits, and a local folder is mounted into the sandbox writable, so the agent can edit your files. Commit or stash first, and prefer staging with a dedicated test account over production data and real credentials.
