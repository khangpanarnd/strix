What you can scan

Code on disk, a repo, or a live app.

Same command shape, different target. Add --mount for a large repo, or --target-list to queue several at once.

A local folder

Point at source already on disk.

strix --target ./app-directory

A Git repository

Clone and scan straight from a URL.

strix --target https://github.com/org/repo

A running web app

Attack a staging URL end to end.

strix --target https://your-app.com

An authenticated flow

Hand it credentials for a test account.

strix --target https://your-app.com \ --instruction "test as user:pass"
Quick start

From zero to a first scan.

The first run pulls the sandbox image, so allow a few minutes. Your model settings are saved to ~/.strix/cli-config.json, so you only set them once.

Before you scan

  • Docker installed and running
  • Python 3.12+ and uv
  • An LLM API keyfrom a provider your team has approved
  • Permission to testwhatever you point it at

1 · Run a quick scan on the current directory

uv run strix -n --target ./ --scan-mode quick

2 · Scan only what changed against main

strix -n --target ./ --scan-mode quick --scope-mode diff --diff-base origin/main

3 · Open the results

strix view

Control cost and resumption with --max-budget-usd and --resume. The -n flag skips the interactive screen and exits non-zero on findings.

Data and privacy

You already know where your data goes.

Strix is local by design. The only thing that leaves your machine is what you send to your own model provider.

stays local On your machine

  • The sandbox, where the agents run and attack.
  • Every finding, log and report in strix_runs/.
  • The viewer, which listens only on 127.0.0.1 behind a private tokened link.

leaves Goes to your model provider

  • The agents' prompts, which include the code and responses they are analysing.
  • This applies to any hosted model you configure.
  • Point LLM_API_BASE at an approved internal endpoint or a local model such as Ollama or LM Studio if the code is sensitive.

Only test apps you own or have written permission to test. Strix runs real exploits against its target — prefer a staging environment and a dedicated test account over production data and real credentials.
